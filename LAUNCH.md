- [i] **Root cause of the notification-link and checkout-domain problems is one setting, and it is
  documented Shopify behaviour rather than a misconfiguration.** There is **no shop-wide primary
  domain**: "primary" is a property of each *target*. The Storefront API defines `Shop.primaryDomain`
  as "The primary domain of the shop's **Online Store**", and Liquid's `{{ shop.url }}` / `shop.domain`
  follow the same value. Verified live: `{ shop { primaryDomain { url } } }` →
  `https://gqrjsh-ha.myshopify.com`, `cartCreate` → `checkoutUrl: https://gqrjsh-ha.myshopify.com/cart/c/…`.
  The "Primary" badge on `sisuhomeware.com` inside the **Sisu (Production)** group is a *different object* —
  it tells Oxygen which domain that environment serves — and it does not feed `shop.url`.
  Why it reads `myshopify.com`: help.shopify.com/en/manual/domains/domain-type/domain-target-change —
  *"If you reassign the primary domain to a different target, then the previous target's primary domain
  reverts to its `myshopify.com` address."* Retargeting the apex to Hydrogen did exactly that.
  **Therefore: to move `{{ shop.url }}` and `checkoutUrl` onto a branded domain, some domain must sit on
  the Online Store target and be that target's primary.** No app code is involved:
  `app/routes/cart.tsx:109` links to `cart.checkoutUrl` verbatim, and `PUBLIC_CHECKOUT_DOMAIN`
  only feeds the CSP in `app/entry.server.tsx:19`.
- [i] **Checkout paths are served by the Online Store target, not the Hydrogen one.**
  `www.sisuhomeware.com/cart/c/<token>` → **301** to `gqrjsh-ha.myshopify.com/cart/c/<token>`
  (Shopify's auto-redirect to the Online Store primary), which then → 302 into Shop Pay /
  `gqrjsh-ha.myshopify.com/checkouts/cn/…`. So a domain targeted at the Online Store *does* serve
  checkout. And an Oxygen-targeted domain never can — see step 8 of the runbook, proven against
